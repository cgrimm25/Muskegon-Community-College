# CIS 270A Project 8: Static Binding & Modular Architecture

## Overview
This project demonstrates the transition from dynamic program calls to highly efficient static binding (bind-by-copy) within the IBM i Integrated Language Environment (ILE). By refactoring standalone programs into discrete modules, the application leverages a main procedure module (`PRJ8MAIN`) that directly calls four statically bound "Nomain" subprocedures (`MODID`, `MODPASS`, `MODFOUR`, and `MODDATE`). These modules are compiled independently, grouped within a custom binding directory, and linked into a single, high-performance executable program that generates a formatted customer audit report.

---

## File Directory
* **`PRJ8MAIN.RPGLE`**: The main procedure module. It manages the primary database read loop, handles printer overflow, and executes the bound subprocedures to process data before writing to the printer file.
* **`MODID.RPGLE`**: A utility subprocedure compiled as a `Nomain` module. It translates first and last names to lowercase and formats a normalized user ID.
* **`MODPASS.RPGLE`**: A security subprocedure compiled as a `Nomain` module. It extracts initials, appends the customer number, and adds formatting tokens to generate a password.
* **`MODFOUR.RPGLE`**: A data masking subprocedure compiled as a `Nomain` module. It extracts and returns the last four digits of a packed customer telephone number.
* **`MODDATE.RPGLE`**: A date arithmetic subprocedure compiled as a `Nomain` module. It converts legacy numeric dates to native ISO formats and calculates a 30-day future reminder date.
* **`PRJ08PRTF.PRTF`**: The externally described printer file Data Description Specifications (DDS) for the final report layout.
* **`Project 8 Instructions.pdf`**: The technical requirements detailing the static binding process, binding directory configuration, and module compilation steps.
* **`PRJ8MAIN-OUTPUT.pdf`**: The final spooled output print stream confirming the successful bind-by-copy execution, returning calculated parameters from all four subprocedures directly into the report detail lines.

## ILE Compilation & Static Binding Framework
The core objective of this project is to assemble a single program (`*PGM`) object from multiple independent module (`*MODULE`) objects. This is achieved through a strict IBM i compilation pipeline:

### 1. Independent Module Generation (`CRTRPGMOD`)
Instead of compiling directly to an executable program, each RPGLE source file is compiled into a separate, non-executable binary module object. 
* The four subprocedures utilize the `Ctl-opt Nomain;` control specification to prevent the compiler from generating main-procedure cycle code, optimizing them purely for exported calls.

### 2. Binding Directory Configuration (`CRTBNDDIR` & `WRKBNDDIRE`)
To manage the linkage of multiple modules efficiently, a Binding Directory (`PRJ8BINDER`) is created. 
* All five modules (`PRJ8MAIN`, `MODID`, `MODPASS`, `MODFOUR`, `MODDATE`) are systematically added into the directory reference list using the `WRKBNDDIRE` command.

### 3. Executable Program Linkage (`CRTPGM`)
The final application is minted by binding the modules referenced in the directory into a single executable block. 
* The `CRTPGM` command is executed, explicitly designating `PRJ8MAIN` as the Program Entry Procedure.
* Validation is confirmed via `STRPDM` (Option 2 - Work with Objects), ensuring all five `*MODULE` objects exist alongside the final compiled `*PGM` object for `PRJ8MAIN`.

## Report Print Specifications (`PRJ08PRTF`)
The output matches the legacy report structure, mapping the returned values from the static subprocedures into an externally described printer file:
* **`HEADING`**: Triggers on page overflow (`SKIPB(1)`), outputting system dates (`DATE`), page numbers (`PAGNBR`), and the developer signature.
* **`DETAIL`**: Streams individual customer records (`SPACEA(1)`), aligning the processed parameters (`USERID`, `PASSWORD`, `LAST4PHONE`, `SENDEMAILR`) generated by the bound modules. Native dates are rendered using the standard `DATFMT(*USA)` mask.
