# Project 3: Wibaux University Payroll Register Report

## Overview
This project generates a comprehensive **Payroll Register Report** for hourly employees at Wibaux University. It demonstrates advanced arithmetic handling in free-form RPGLE, the execution of standalone arithmetic rounding mechanisms (`Eval(h)`), and data structure overlay mappings to isolate string characters. The program structures relational database boundaries against an input employee master table and accumulates running math metrics to emit final report balance blocks.

## File Directory
* **`PROJECT3.RPGLE`**: The application processing logic written in free-form RPGLE. It configures named evaluation constants, parses records sequentially through a priming loop, computes multi-tier tax allocations with rounding rules, and tracks grand total accumulations.
* **`PRJ3PRTF.PRTF`**: The external printer file Data Description Specifications (DDS) organizing the visual presentation grid, detailing customized edit codes, zero-suppression masks, and Social Security Number string mapping format slots.
* **`Project 3 Instructions.pdf`**: The official assignment scope defining calculation metrics, target tax rates, database schemes, and the programmatic printchart criteria.
* **`PROJECT 3-OUTPUT.pdf`**: A sample execution printout of the final compiled report confirming strict compliance with spacing, name truncation, and currency alignment layout matrices.
* **`WUHRLYP.PF-DTA.pdf`**: A reference data printout showcasing sample production records stored inside the underlying database file system.

## Core Technical Specs & Business Logic

### 1. Named Constant Tax Allocations
To eliminate hardcoded magic numbers and enforce clean administrative maintenance, corporate withholding thresholds are isolated using explicit named constants at the top of the definition block:
* **Federal Tax Withholding**: Evaluated at a flat rate of `18%` (`0.18`).
* **State Tax Withholding**: Evaluated at a flat rate of `5%` (`0.05`).
* **FICA Deduction**: Evaluated at a flat rate of `7.51%` (`0.0751`).

### 2. Name Truncation via Data Structure Overlays
Per project design rules, only the first name's initial is permitted to pass onto the printer layout line. The program achieves this cleanly at the memory layout level by binding an internal data structure:
* Fields pull raw string values into the primary `FNAME` string buffer.
* An internal indicator variable (`INITIAL`) overlays the primary field at position 1, cleanly capturing the first character without messy substring string-manipulation functions.

### 3. Payroll Arithmetic & Precise Rounding
The iteration engine handles employee arithmetic using half-adjust parameters (`Eval(h)`) to ensure perfect accounting accuracy:
* **Gross Pay**: Calculated by multiplying standard hours by the pay rate, then appending overtime distributions multiplied at time-and-a-half (`1.5 * RATE * OTHRS`).
* **Net Pay**: Generated by calculating independent tax structures with rounded fractions, summing them up, and subtracting total liabilities from gross balances.
* **Accumulated Totals**: Tracks rolling sums across all five monetary columns throughout the entire execution lifetime, printing out the final matrix metrics within a dedicated `TOTAL` subfile format only after the physical file data is completely exhausted.
